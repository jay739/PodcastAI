# Working, fully pinned dependency set for the web backend.
# Verified on Apple Silicon, macOS 27.3, Python 3.12.13, 2026-11-24.
#
# Install with:
#   python3.12 -m venv .venv && .venv/bin/pip install -r requirements-macos.txt
#
# Why this file exists instead of Backend/requirements.txt
# -------------------------------------------------------
# Those pins are from 2021 to 2023 and no longer resolve or load here.
# torch==2.1.2 has no wheels past Python 3.11, pandas==1.5.3 predates 3.12, and
# the old scipy wheel fails to dlopen on this macOS with "section
# '__DATA/__thread_bss' has a zero-fill section type", which crash-looped the
# service until the venv was rebuilt.
#
# Everything here is pinned to an exact version on purpose. Unpinned torch and
# transformers are what broke the previous fresh install: they resolve to
# whatever is newest and drag incompatible numpy and scipy along with them.
# Re-pin deliberately after testing, do not loosen these to ranges.
#
# requirements.txt also omits ten modules the code actually imports. Four are
# module-level in the startup chain and unavoidable: textstat, nltk and spacy
# (pdf_processor.py) and openai (llm_service.py:7 imports it and assigns
# openai.api_key at module scope even though Ollama is the provider; nothing is
# called and no key is set). bertopic and gensim are both needed because
# pdf_processor.py:177 calls get_topic_model and a short PDF yields a single
# chunk, which BERTopic cannot fit, so the gensim fallback is the normal path
# for short documents.
#
# Deliberately NOT included: TTS (Coqui XTTS), bark, kokoro and modal.
# tts_service.get_tts_generator imports each backend lazily and
# PODCAST_WEB_TTS=piper, so none of them is loaded at runtime. They are heavy
# and pin conflicting torch versions.
